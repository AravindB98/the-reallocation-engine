### The three attestation errors caught in resume.json

1. **CodeSentinel, "cut false positive rate from 0.789 to 0.111 vs single-prompt baseline".** The column is FP/(FP+TP), a false discovery rate, because the suite has no true negatives; the figures come from one real-model run on a 10-sample suite on 2026-04-20, and the two runs before it that afternoon returned zero findings. The repository's own README (lines 144 to 159 at commit 49ea00d, which I corrected on 22 October) says all of this. The resume, generated two days later, still carries the old claim. Corrected in the record to "30 false positives became 1 in the one real-model run on record"; the resume line must change.
2. **QueryCraft, "100% improvement on SELECT-clause generation over the base model".** The README table is "Has SELECT: 0% to 100%", a presence check (the base model emitted no SELECT at all). Exact match went from 0% to 8%, and the RAG layer reduced the valid-SQL rate from 96% to 82%. Corrected to the table's actual numbers; the resume line must change.
