**The CRLF step** (`00-terminal-history.txt`):
- **Six E3 errors.** The first Git Bash `verify` failed with **6 E3 errors**

  `file claude.md` reported `with CRLF line terminators` (`00:40`).
- **Fix.** `git config core.autocrlf false`, then
  `git rm -rq --cached .` and `git reset --hard` (`00:43-50`). Afterwards

  3 warnings (`00:62-72`).

**Why doctor said 0/33 and then 33/33.** The first baseline misreported the
repository. Every recipe does carry frontmatter; the line endings hid it.
- With `autocrlf=true` the checkout had CRLF line endings (`00:35-40`), so
  every line ends in `\r`.
- `doctor.mjs` reads frontmatter by splitting on `\n` and matching each line
  against `/^([a-z_]+):\s*(.*)$/i` (`scripts/doctor.mjs:85-87`).
- In JavaScript, `.` does not match `\r` and `$` must reach the end of the
  string. So `status: DRAFT\r` never matches, no `status` is found, and every
  recipe counts as "missing frontmatter".
- On the LF fresh clone the same 33 files parse, and declared TODOs (318)
  equal body markers (318) (`01-doctor.txt:59`).

branch adds to the default conformance surfaces:

means findings, 2 means a usage or environment error (`scripts/pii-scan.mjs:9`).

does not appear. It also doesn't read commit author headers.
